## How I Work

I don't start by asking, **"What software should we build?"**

I start with:

**01 — Understand**

What's actually getting in the way?

I look at the business, the people involved, the existing workflow, and where the friction exists.

**02 — Define**

What does the solution actually need to do?

The problem becomes a clear set of requirements, users, workflows, and outcomes.

**03 — Build**

How do we turn the solution into something useful?

I design and develop around the requirements, with attention to usability, performance, reliability, and maintainability.

**04 — Improve**

How can the solution become more useful over time?

Once people use it, we learn what works, what doesn't, and what should change.

**The goal isn't to build more technology. It's to build something that makes the business work better.**
